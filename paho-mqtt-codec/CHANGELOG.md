# paho-mqtt-codec: MQTT packet codec for Rust.
#

All notable changes to this crate will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased] - v0.1.0

Initial release. A pure-Rust, `no_std`-compatible encoder and decoder for every MQTT control packet in protocol versions 3.1, 3.1.1, and 5.0, for use by any MQTT client library, broker, proxy, or tool. Developed alongside, and used by, the Eclipse Paho MQTT Rust client v2, but with no dependency on it.

### Design

- One struct per packet type, shared across protocol versions; v5-only fields (reason codes, properties) are present everywhere and simply not written to the wire on a v3 connection. `Connect` carries its own `version` and is decoded without knowing it in advance, as a server must.
- Two-phase decoding: `RawPacket::decode` frames one packet out of a `BytesMut` read buffer (returning `None` until it is complete) and `Packet::from_raw` parses it for the negotiated version. `RawPacket::decode_max` enforces a maximum packet size before the body is buffered. `RawPacket::packet_type()` gives the type before parsing.
- Zero-copy where the protocol allows: decoded PUBLISH payloads are slices of the receive buffer; `Packet::encode_split` returns the payload separately so it can be written with a vectored write instead of copied. `Packet::encode` reserves its exact output size once and leaves the buffer untouched on error.
- Strict decoding, classified as the specification classifies it: `Error::MalformedPacket` (cannot be parsed: lengths, reserved bits, invalid UTF-8, unknown types, non-minimal variable-byte integers) versus `Error::ProtocolError` (parses but breaks a rule: packet ID 0, DUP on QoS 0, a property out of range, repeated, or not allowed in that packet, a reason code not allowed in that packet, empty subscription or acknowledgement lists), plus `TopicNameInvalid`, `TopicFilterInvalid`, `PacketTooLarge`, `UnsupportedProtocolVersion`. `Error::reason_code()` gives the DISCONNECT (or CONNACK) reason code to send back.
- The same rules apply to encoding, so a badly built packet fails locally rather than at the peer: string and binary fields over 65 535 bytes, U+0000 in strings, wildcards in a topic name, misplaced wildcards or a malformed `$share/…` prefix in a topic filter, and properties that are invalid for their packet. A packet identifier of zero, an empty SUBSCRIBE/UNSUBSCRIBE filter list, an empty SUBACK/UNSUBACK code list, and a repeated Subscription Identifier outside a PUBLISH are likewise rejected on both encode and decode.
- A packet that a v3 connection cannot express is refused rather than truncated: non-empty properties, reason codes in an UNSUBACK, or a SUBACK return code outside the four v3 values (0x00–0x02, 0x80) fail to encode for v3, and the last is also a Malformed Packet on decode. A QoS 0 PUBLISH with a packet identifier set is likewise refused.
- Every packet must account for exactly its remaining length: bytes left after the last field — a PINGREQ with a body, a v3 DISCONNECT with a payload, a CONNACK longer than its fields — are a Malformed Packet rather than silently discarded.
- `Properties` validates on `push` (value range, wire type, repeated non-repeatable identifiers) and remembers the outcome, so encoding costs one check rather than one per property; it caches its wire size. `PropertyId::is_allowed_in`, `ReasonCode::is_allowed_in`, and `PropertyContext` expose the specification's per-packet tables.
- The `topic` module exposes the name and filter validation the codec uses, including `split_shared` for shared subscriptions.
- One rule for a field the connection's protocol version cannot carry, documented under `# Version mismatches`: if v3 has no such field — properties anywhere, the reason codes of DISCONNECT and the PUBACK family, UNSUBACK's reason-code list, `ConnAck::session_present` on v3.1 — encoding it for v3 is a `ProtocolError`; if the field exists but the value is reserved in that version — a CONNACK or SUBACK return code out of range — it is a `MalformedPacket`, as it is on decode. Neither is silently dropped. The DISCONNECT and PUBACK reason codes and v3.1's `session_present` were previously dropped without a word, so a v3 PUBACK built with `NotAuthorized` went out as `Success`.
- AUTH has no shorthand form. Unlike PUBACK (§3.4.2.1) and DISCONNECT (§3.14.2.1), §3.15.2 has no clause letting the Reason Code or the Property Length be omitted, and §3.15.2.2.2 makes an AUTH with no Authentication Method a Protocol Error, so every AUTH encodes to at least a reason code, a property length, and that method. `Auth::default()` is consequently a value rather than a sendable packet.
- Four validation gaps closed, each of which let the encoder build a packet the decoder would reject: a Will topic is now checked as the topic *name* it is (non-empty, no wildcards — it has no topic alias to stand in for it, so this holds on v5 too); `dup` on a QoS 0 PUBLISH is refused (MQTT-3.3.1-2); a v3 CONNECT with a password but no username is refused (MQTT-3.1.2-22); and Authentication Data with no Authentication Method is refused wherever the pair may appear — CONNECT, CONNACK, and AUTH (§3.1.2.11.10, §3.2.2.3.18, §3.15.2.2.3).
- Typed accessors on `Properties`, mirroring the `push_*` helpers: `get_byte`, `get_u16`, `get_u32`, `get_var_int`, `get_binary`, `get_string`, and `get_string_pair` each return the value already unwrapped, or `None` if the identifier is absent *or* holds a different type. Each has a `_at(id, idx)` form for the identifiers that may repeat — `UserProperty`, and `SubscriptionIdentifier` in a PUBLISH — built on a new `get_at`, which indexes within the identifier rather than the whole list. `get` still borrows the `PropertyValue` for callers that want to avoid the clone. `get_u32` accepts either 32-bit wire form, a `U32` or a variable-byte integer, while `get_var_int` is exact about it.
- `Properties::push_var_int` completes the `push_*` set, wrapping the `Property::new_var_int` constructor.
- User properties have their own routines, as in v0.14: `push_user(key, val)`, `user_iter()` over the pairs in order, `get_user(key)` for the first match (kept under v0.14's name, `find_user_property`, as a `#[deprecated]` alias), and `remove_user(key)`, which takes every entry with that key and reports how many. `get_all(id)` walks the values of one identifier (v0.14's `iter(code)`; the name differs because `iter()` here walks the whole collection). `user_iter` and `get_user` borrow rather than allocating a `String` per item, so they differ from v0.14 in return type.
- `Properties::retain(f)`, `remove(id)`, `remove_user(key)`, and `clear()` can take properties back out. `retain` is the general form, for a condition on the value rather than the identifier, and the other two are built on it. Removal recomputes the cached wire size and the seen-identifier set, so the encoded length stays correct and an identifier freed by a removal can be pushed again — including the case where dropping a repeated property makes an invalid list valid.
- `QoS`'s variants are `QoS0`, `QoS1`, and `QoS2`, with `AtMostOnce`, `AtLeastOnce`, and `ExactlyOnce` as associated constants naming the same values — the reverse of how they were first written. Both spellings work at every call site. Under the `serde` feature a value serializes as `"QoS0"`, `"QoS1"`, `"QoS2"`, and deserializes from either spelling, so data written with the earlier variant names still reads.
- One constructor rule, keyed to the protocol version a packet exists in: a packet that v3 also has takes no properties in `new` and has a `with_properties` alongside it (`ConnAck`, `Will`, `PubAck` and its aliases, `Subscribe`, `SubAck`, `Unsubscribe`, `UnsubAck`, `Disconnect`; `Publish` and `Connect` have builders instead), so a v3 caller is never asked for a type it cannot use. `Auth`, the one packet v5 introduced, takes properties directly in `new` — there is no v3 caller to spare, and §3.15.2.2.2 requires every AUTH to name its Authentication Method; the bare `Success` that ends an exchange is `Auth::default()`. Encoding a non-empty property set for v3 is an error rather than a silent drop, so the wrong constructor is caught rather than quietly changing the wire output.
- Where a field is v5-only, `new` leaves it out too, so the v3 form is reachable without naming v5 types: `PubAck::new(id)`, `UnsubAck::new(id)`, and `Disconnect::new()` are the bare packets v3 can express, and the reason codes move to `with_properties` alongside the properties.
- `From<Publish> for Will` turns a message into the Will that would publish it, carrying the topic, payload, QoS, retain flag, and properties, and dropping the `dup` and `packet_id` a server assigns for itself. A `TopicAlias` or `SubscriptionIdentifier` is legal in a PUBLISH but not a Will, and is caught when the CONNECT is encoded rather than dropped in the conversion.
- `PublishBuilder` and `ConnectBuilder` build those two packets a field at a time — `Publish::builder().topic(..).payload(..).qos_with_id(QoS::QoS1, id).finalize()`, `Connect::builder().version(..).client_id(..).username(..).finalize()` — for the two packets whose seven and eight fields make a constructor per combination impractical, and so the only two with no `with_properties`. Like the constructors they do not validate; the packet is checked when it is encoded.
- No packet has more than two constructors. `Auth::new` and the `with_properties` of `PubAck` (with its aliases), `UnsubAck`, and `Disconnect` take `properties` as anything convertible into `Option<Properties>`, so `None` stands for an empty set — that covers the reason-code-only wire forms without a third constructor for each.
- Lenient in one place by default, deliberately: a CONNACK that refuses the connection but sets Session Present decodes with the flag cleared and the reason code kept, since the reason code is what the receiver needs. `DecodeOptions::STRICT` (via `Packet::from_raw_with` / `ConnAck::decode_with`) reports it as a `ProtocolError` instead, for conformance testers and analyzers; the struct is `#[non_exhaustive]` so further strictness controls can be added.
- `no_std` with `alloc`; the `std` feature is opt-in and forwards to dependencies. The `serde` feature derives `Serialize`/`Deserialize` for every public data type. Verified in CI on a bare-metal target.
- Criterion benchmarks covering encode and decode of every packet type, and two `cargo-fuzz` targets: byte-level (`decode`) and structure-aware (`roundtrip`, which builds valid packets and checks encode → decode is the identity).
