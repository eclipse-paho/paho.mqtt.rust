# R7.5: persistent futures in the loop — measured and declined (2026-10-18).

## 1. Syscalls per message today (strace -f -c, n=20000, null broker)
#
# scenario           recvfrom  of which  epoll_ctl  epoll_wait
#                              EAGAIN                        
# smol pub1-seq      2.088     1.088     1.275      -
# smol rtt           2.075     1.075     1.901      -
# tokio pub1-seq     1.000     0.000     0.000      2.825
# tokio rtt          1.000     0.000     0.000      3.968
#
# Note the shape: smol's EAGAIN count is ~1 per *read*, not per pass. tokio makes
# no speculative read at all, because its TcpStream checks the driver's cached
# readiness before trying; async-io has no such cache and tries the syscall first.
# Under load the EAGAIN is amortised away: smol sub cb is 0.0035 recvfrom/message.

## 2. Does pinning the read future help? No.
#
# A standalone program (smol 2 + async-io 2.6): one task selects over a socket
# read and a 50us timer, with the peer sending only every tenth tick, so most
# passes are woken by something other than the read — the shape R7.5 describes.
# Two variants, one creating the read future per pass, one keeping it pinned and
# rebuilding only after it completes. 2000 passes each:
#
#   fresh:  1.473 EAGAIN recvfrom/pass,  2.336 epoll_ctl/pass
#   pinned: 1.461 EAGAIN recvfrom/pass,  2.223 epoll_ctl/pass
#
# Within noise. Reading async-io 2.6 says why:
#   - AsyncRead::poll_read tries the read on every poll, new future or not, so the
#     EAGAIN is per poll rather than per future;
#   - Source::poll_ready keeps the registered waker when will_wake() matches, so
#     re-creating the future does not re-register. The epoll_ctl calls come from
#     re-arming after each delivered event, which no caller can avoid.

## 3. The gap R7.5 was meant to close (5 reps interleaved, medians, ivcsw-filtered)
#
# scenario    tokio cpu/msg  smol cpu/msg  ratio
# pub0-seq          16.88        14.31   0.85   <- smol cheaper where nothing is read
# pub1-seq          23.84        30.32   1.27
# rtt               36.90        43.75   1.19
#
# Syscalls per message are comparable (smol ~5.7, tokio ~6.3 — tokio makes more),
# so the remaining difference is not syscall-bound and R7.5 could not have closed
# it even if pinning had worked.
